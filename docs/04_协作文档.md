## 一、角色总览（学习导向版）

| 成员 | 主要职责 | 主要学习收益 | 不负责 |
|---|---|---|---|
| **A** | 全部前端（Swing/Controller/Chart）+ `QueryService` + `ExportService` + **F-13 PageRank** + **F-16 情感趋势/拐点检测** + 打包/README/PPT | 图挖掘（PageRank）+ 时序分析（拐点检测）+ Swing GUI + JFreeChart | 数据导入、TSV 解析、F-12 共现表构建、F-14 主题热度、F-15 K-Means |
| **B** | 项目基础设施 + 全部 Model + 全部 DAO + `ImportService` + `cleanInvalidData` + **F-12 共现网络构建** + **F-14 主题热度** + **F-15 K-Means 聚类** + `AnalysisServiceImpl` 装配 | 数据工程（半结构化解析、JDBC 批量、SQLite 调优）+ 文本挖掘（K-Means）+ 图建模 | UI、Controller、图表、F-13 PageRank、F-16 情感分析、导出 |

### 算法分配的核心原因

| 算法 | 归属 | 为什么这样分 |
|---|---|---|
| F-12 共现网络构建 | **B** | 是 F-13 的前置；本质是 SQL 聚合，与 B 的数据工程职责一致 |
| **F-13 PageRank 焦点人物** | **A** | 与 F-20 共现网络图垂直耦合 —— A 既写算法又渲染节点大小，端到端学透 |
| F-14 主题热度排行 | **B** | `GROUP BY` 时间粒度聚合，技术含量与 B 的查询/聚合能力匹配 |
| **F-15 K-Means 主题聚类** | **B** | 机器学习经典算法，是 B 的学习重点 |
| **F-16 情感趋势 + 拐点检测** | **A** | 与 F-23 情感仪表盘垂直耦合 —— A 自己写算法自己画拐点 |

### 协作核心原则

1. **B 先 A 后**：B 的基础设施 + 接口先行，A 才能编译
2. **接口先于实现**：B 在 W2 末交付所有 Service 空实现 + 共享 record，让 A 编译过；之后 B 替换为真实现
3. **算法上行**：A 把 F-13 与 F-16 算法类**交付给 B**，B 在 `AnalysisServiceImpl` 中装配
4. **Mock 先行**：A 在等 B 真实现时用 Mock 跑 UI
5. **每周一次联调**：每周三晚集中合并 develop + 冒烟测试

## 二、Git 协作规范

| 项目 | 约定 |
|---|---|
| 主分支 | `main` —— 仅 W7、W8 合入可发布版本 |
| 集成分支 | `develop` —— 每个模块完成即合入 |
| A 工作分支 | `feature/frontend-A`（含 QueryService、ExportService、PageRank、SentimentTrend） |
| B 工作分支 | `feature/backend-B` |
| 合并方式 | PR / 本地 merge，合并前 `git pull --rebase origin develop` |
| 提交频率 | 至少每天 1 次（评分项「Git 提交记录」要求） |
| 禁止 | 直接向 `main` 推送 / 修改对方目录文件 / 强推 |
